# 调试工具并回主包：随包分发、默认关闭、挂在插件自己的页面

Status: accepted（取代 [ADR-0003](0003-test-capability-lives-outside-the-plugin.md)）

ADR-0003 把调试面板拆成仓库内 `dev/` 的独立插件，理由是"测试代码不该随发布包分发"。实际用起来有两个问题：

1. **用户拿不到它**。面板要额外装一个 `file:` 包，而 DSH 的插件页只认 registry 包名——多出来的这个包既不能更新、也在插件列表里显示成一串裸包名。删除它又要先卸载旧包，卸载一次就丢掉了面板的全部状态。
2. **它测不到"实际使用"**。独立插件只有自己的探针，用户没法在不改造真实场景的前提下验证"真实会话结束时到底弹不弹"。这正是这次修复要回答的问题，而回答它需要面板与提醒共用同一套前台判定。

所以决定并回主包，并加三道约束：

- **默认关闭**。`devToolsEnabled` 初值是 `false`，关着的时候服务侧直接拒绝三个写入口（前台覆盖、临时投递、按原因模拟）——外部即使拿到 `sessionStatusTest` 服务也改不动提醒行为。开关只在内存里，页面重载即回到关闭。
- **挂在插件自己的页面**（`plugins.detail.section`），不放设置页。它描述的是这个插件自身的能力，不是 DSH 的全局设置；`settings.section` 曾经被删除，不允许回潮（`npm run check:production` 守着这条）。
- **面板只在本插件的详情页渲染**：`plugins.detail.section` 对每个插件都会渲染，组件按 `subject.pkg.name` 过滤，别人的插件页不会带上我们的调试工具。

## Consequences

- 发布包里多了一段默认不生效的 UI 代码（约 18 KB 源码，压缩后几 KB）。`check:production` 从"断言没有调试 UI"改成"断言历史残留没有回潮 + 该有的能力都在 + 初值必须是 false"。
- `sessionStatusTest` 服务保留：面板就是它的第一个消费者，外部开发插件仍可 `inject` 它。
- 前台覆盖是**全局**的：强制失焦后，真实会话结束也会弹——这正是"测实际使用"的通道，面板文案必须把这点说清楚，免得用户以为它只影响探针。
- 调试能力的默认关闭靠代码初值保证，不靠配置项——Profile 不需要任何改动，普通用户升级后行为不变。
